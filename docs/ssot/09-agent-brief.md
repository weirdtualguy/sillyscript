## 14. Agent Brief & Development Specifications
<!-- id: agent-brief | world: W6 | difficulty: 4 | prereqs: architecture-mental-model, kip21-lane-rules-proving | status: unverified -->

When configuring automated code-generation agents or architecting a new Toccata application, engineers must first triage whether the workload belongs on a pure Layer-1 Covenant or a Layer-2 Based App. This triage depends on six preflight design questions: (1) whether application state naturally resides in a single UTXO, many parallel UTXOs, or a high-contention shared off-chain state root; (2) which exact security violations must be impossible (unauthorized genesis, invalid transition, stale branch spend, negative-value underflow, or invalid exit); (3) which guarantees are enforced by consensus (covenant_binding, SeqCommit) versus script execution (require, validateOutputState) versus off-chain indexers; (4) what descriptor artifacts (prefix, suffix, state_layout, template_hash) a KCC-0001 reader/writer indexer requires to reconstruct live state; (5) whether output validation can be generated via #[covenant] macros or Argent lowering; and (6) what ZK proof, if any, is verified on L1.

| Specification Dimension | L1 Covenant Engineering Brief | Based-App (L2 ZK + KIP-21 Lane) Engineering Brief |
| --- | --- | --- |
| **Target Execution Model** | Pure Layer-1 UTXO covenant written in Silverscript (pragma silverscript ^0.1.0;). | Hybrid Layer-1 user-lane payload sequencing + off-chain execution + L1 ZK settlement covenant. |
| **State Storage & Identity** | State is encoded in the P2SH redeem script preimage ([prefix][state][suffix]); persistent lineage uses KIP-20 covenant_id. | Global shared state root maintained off-chain; committed on L1 inside a singleton settlement covenant UTXO. |
| **User Operation Format** | Direct spend of one or more covenant UTXOs satisfying the covenant's entry or #[covenant] policy. | Ordinary Transaction V1 carrying payload and user-lane subnetwork_id ([ns: 4B, 0x00 \* 16]); **not** a covenant spend per op. |
| **Required Pre-Coding Checklist** | Identify mutable State fields vs. constructor constants; select topology (1:1, 1:N, N:M, or multi-contract ICC); specify foreign template validation (validateOutputStateWithInputTemplate); define KCC-0001/0020 descriptors and V1 compute_budget. | Define 4-byte lane namespace and gas policy (\le 10^9/block); specify payload schema, state root, and MergesetContextHash / MinerPayloadRoot dependencies; choose proof mode (RISC Zero 0x21 vs. Groth16 0x20); define settlement cadence and L1 exit outputs. |
| **Mandatory Safety Guards** | Constrain all signed int output amounts \ge 0; precede fixed-array casts with .length checks; validate leader signatures and all input branch invariants. | Anchor every settlement proof between two OpChainblockSeqCommit (0xd4) checkpoints; treat vprogs as an evolving reference rather than a frozen SDK. |
